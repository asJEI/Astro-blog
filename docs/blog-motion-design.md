# 北海 · 风起时：博客动效设计与实施方案

> 远处有缓慢流动的风，近处有正在写下的文字。

- 文档日期：2026-09-28
- 项目：北海个人博客
- 基础主题：北海 · 未完成时
- 状态：已按本方案接入首页与全站交互（2026-09-28）
- 交付目标：在现有主题上增加有个人辨识度的动效，保持阅读舒适，并沿用现有静态部署流程。

---

## 1. 项目背景

博客目前采用 Astro、TypeScript、Tailwind CSS 与局部 React 组件，默认进行静态构建。项目 README 记录的发布方式为 Cloudflare Pages 自动部署，构建命令为 `npm run build`，输出目录为 `dist/`。

现有界面已经具备：

- 首页二次元背景、标题入场和基础悬停效果。
- 暖纸色日间主题与深色夜读主题。
- 首页左侧「桌边」和右侧文章列表。
- 经历、幽微、观察三个内容分类。
- Astro `ClientRouter` 页面导航。
- 音乐播放器及跨页状态保留。
- 文章目录、阅读进度、图片查看、关联阅读与后记。
- 基础的 `prefers-reduced-motion` 支持。

本次动效设计以这些能力为基础，不改变文章地址、内容分类和现有阅读结构。本方案中的参数为初始设计值，性能指标为验收目标，并非已经测得的结果。

## 2. 设计目标

### 2.1 核心气质

关键词：**辽阔、幽微、留痕、生长。**

动效主题「风起时」是「未完成时」的延伸，不替换网站名称。它把背景中的远方、文字中的成长与页面中的时间感连接起来。

访客进入首页时，应感到画面有轻微呼吸；开始阅读后，动效逐渐退到边缘。

### 2.2 设计原则

1. **内容优先**：文字和入口立即可用，动画不作为访问内容的前置条件。
2. **空间分工**：持续氛围集中在首页首屏，文章正文保持稳定。
3. **动作克制**：位移小、速度缓、粒子稀疏，不干扰背景人物与标题。
4. **反馈清楚**：点击、悬停、聚焦和播放状态有明确反馈。
5. **允许静止**：用户可以关闭装饰性动效，并尊重系统减少动态效果设置。
6. **持续可维护**：配置集中，动画有完整的初始化、暂停和销毁流程。

### 2.3 第一版范围

| 包含 | 暂不包含 |
| --- | --- |
| 首页微光粒子 | 粒子连线、点击爆炸、鼠标拖尾 |
| 首屏分层入场 | 加载进度仪式、强制等待开场 |
| 桌面轻微背景视差 | 手机陀螺仪与设备方向权限 |
| 分区显现和分类专属反馈 | 每个正文段落的滚动入场 |
| 页面淡入淡出 | 三维翻书、大幅旋转或缩放 |
| 播放状态音柱 | 真实音频频谱分析 |
| 动态偏好控制 | 后端服务、账号同步 |

## 3. 首页视觉设计

### 3.1 图层结构

从底到顶排列：

1. 现有背景图。
2. 保证文字可读性的明暗遮罩。
3. 微光粒子画布。
4. 首屏底部渐隐层，让背景和粒子融入页面纸面。
5. 标题、介绍、链接与动态开关。
6. 全站导航。

粒子和背景仅在首屏容器内显示，不延伸到文章列表及正文。画布不参与布局计算，不覆盖交互事件。

### 3.2 微光粒子

粒子像空气中的浮尘、细雪和远处微光。现有桌面背景中已经包含静态光点，新增粒子应先采用低密度，再根据实测画面调整。

| 属性 | 初始设计值 |
| --- | --- |
| 桌面数量 | 24～40 颗，随首屏面积变化，最多 40 颗 |
| 手机数量 | 8～14 颗，最多 14 颗 |
| 主要直径 | 1～3 CSS px |
| 少量近景光点 | 4～6 CSS px，边缘柔和 |
| 不透明度 | 0.08～0.30 |
| 漂移速度 | 3～10 CSS px / 秒 |
| 明暗周期 | 约 6～12 秒，随机错开 |
| 主风向 | 缓慢横向漂移，附带轻微上下浮动 |
| 边界处理 | 在边缘淡出后从另一侧重新进入，不在画面中突然跳位 |

分布与运动规则：

- 左侧文字区域粒子更少、更暗，右侧与中间区域略多。
- 多数粒子小而远，少量粒子稍大，形成轻微空间层次。
- 全部粒子共享一个大致风向，各自速度和相位有小幅差异。
- 明暗变化缓慢，不使用高频闪烁。
- 不出现大面积光晕、彩色光斑和高亮遮挡。

### 3.3 日夜适配

| 模式 | 视觉处理 |
| --- | --- |
| 日间 | 浅色浮尘，少量暖光，优先保证浅色背景上的克制感 |
| 夜间 | 雾白与灰蓝微光，少量灰玫瑰点缀，亮度略高 |

切换主题时，只平滑更新粒子调色，不重新随机生成粒子位置。实际透明度结合背景明暗调整，不要求两种模式使用同一组值。

### 3.4 鼠标反馈

仅在支持精细指针的桌面设备启用：

- 鼠标移动轻微改变风向，变化有平滑跟随。
- 偏移设定上限，避免快速划动导致粒子大范围飞散。
- 鼠标离开首屏后，风向缓慢回归默认值。
- 背景人物和标题不跟随鼠标摆动。
- 不隐藏系统光标，不添加自定义光标。

### 3.5 背景视差

向下滚动时，背景以略慢于页面的速度移动。

- 桌面背景最大位移约 12～20px。
- 保持原图整体构图，不拆分人物与景物。
- 背景适当保留裁切余量，避免位移露出边缘。
- 手机端和减少动态效果模式关闭视差。
- 不劫持滚动，不修改滚轮灵敏度。

## 4. 首屏入场设计

| 时间参考 | 元素 | 效果 |
| --- | --- | --- |
| 页面出现 | 背景、导航 | 立即显示 |
| 0～450ms | 北海、未完成时 | 淡入，上移约 8px |
| 100～550ms | 座右铭与介绍 | 淡入，轻微上移 |
| 180～600ms | 阅读入口 | 淡入 |
| 首屏内容就绪后 | 微光 | 从低透明度逐渐进入 |

约束：

- 不等待粒子脚本或背景图片完成后才显示文字。
- 不使用逐字打字机，避免中文阅读被拆散。
- 不在键盘聚焦后继续让入口保持不可见。
- 同一会话再次返回首页时缩短入场；浏览器后退恢复位置时，不重复完整开场。
- 粒子初始化失败不影响首屏内容。

## 5. 内容区域与交互设计

### 5.1 分区显现

首页「初次见面」「三个方向」「最近写下」首次进入视野时，可以淡入并上移 8～12px，持续约 350～450ms。

- 每个区域只播放一次，不在来回滚动时重复。
- 三个分类之间最多错开 50ms。
- 左侧桌边整体保持稳定，不逐条播放头像、标签、播放器入场。
- 文章列表以区域或可见的小批次显现，避免长串延迟。
- 正文段落直接显示。
- 无脚本时，所有内容默认可见。

### 5.2 分类专属反馈

#### 经历 EXPERIENCE

> 人生没有版本回退，所幸文字可以替我留下每一次提交。

悬停或键盘聚焦时，箭头轻移 2～3px，细线缓慢延伸，体现向前与留痕。

#### 幽微 YOUWEI

> 以铜为镜，可以正衣冠；以人为镜，可以明得失；以史为镜，可以知兴亡；以算法为镜，可以照幽微。

悬停或键盘聚焦时，环形标记轻微扩大，出现一圈低透明度光晕；离开后回到原状，体现照见与回响。

#### 观察 OBSERVATIONS

> 世界不断给出新的问题，而我仍在学习如何提问。

悬停或键盘聚焦时，线形标记轻移，方向箭头变清晰，体现向外探索。

以上效果仅在交互期间出现，不循环播放，也不只依赖颜色表达可点击状态。

### 5.3 列表与链接

- 文章标题在约 150～180ms 内切换重点色。
- 箭头轻微向右上移动，不推动旁边的布局。
- 链接下划线从左向右展开。
- 卡片不大幅弹起，不加入强烈阴影。
- 键盘聚焦有清楚的轮廓，与鼠标反馈同样可发现。

## 6. 内页动效

### 6.1 页面切换

使用现有 Astro `ClientRouter`，主内容采用约 180～240ms 的交替淡入淡出。

- 导航作为稳定参照。
- 已播放的音乐保留状态，不因转场重建音频。
- 主内容不执行大幅横向滑动。
- 前进、后退应正确恢复滚动位置。
- 锚点、分类链接和搜索结果继续使用正常导航行为。
- 不支持相应动画能力时，正常完成页面跳转。

### 6.2 文章阅读

| 元素 | 处理 |
| --- | --- |
| 阅读进度 | 保留现有进度条；没有相关能力时不阻碍阅读 |
| 目录 | 当前章节标记进行短距离平滑移动 |
| 图片查看 | 打开和关闭时短暂淡入淡出，可配合极轻微缩放 |
| 后记 | 保持清楚的展开、收起反馈；不采用固定最大高度裁切长内容 |
| 正文 | 保持稳定，不逐段入场，不持续闪动 |

### 6.3 日夜切换

背景与文字颜色在约 200ms 内过渡。保持原有选择记忆机制，并使首页粒子同步调整调色。

不使用覆盖全屏的强烈扩散动画，避免打断长文阅读。

### 6.4 音乐状态

播放器增加 3～4 根小音柱：

- 播放时轻微起伏，暂停时立即静止。
- 加载与失败状态使用文字反馈。
- 音柱作为装饰，不替代播放、暂停按钮及状态文本。
- 第一版采用 CSS 状态动画，不宣称与音频频谱实时对应。
- 音乐仍由用户主动播放，不绑定页面任意点击来首次播放。

## 7. 动态偏好与无障碍

### 7.1 用户开关

首页首屏角落设置低调的「动态：开 / 关」按钮，使用明确文本与 `aria-pressed` 表达状态，并提供至少 44px 的可触达区域。

开关保存用户偏好，控制粒子、视差及其他装饰性动作。关闭后保留即时的聚焦轮廓、播放状态与阅读定位信息。

### 7.2 决策优先级

1. 系统开启 `prefers-reduced-motion: reduce`：暂停持续装饰性动画，取消入场位移和视差。
2. 用户显式关闭动态：使用静止模式。
3. 其余情况：按设备能力启用标准或轻量模式。

系统减少动态效果开启时，界面显示已遵循系统设置，避免按钮状态与实际行为矛盾。系统偏好发生变化后，当前页面立即响应。

### 7.3 降级规则

| 条件 | 行为 |
| --- | --- |
| 手机或粗指针设备 | 少量粒子，关闭鼠标响应与背景视差 |
| 系统要求减少动态效果 | 静止背景，内容直接显示 |
| 用户关闭动态 | 停止装饰性运动，并记住选择 |
| 首页首屏离开视野 | 暂停粒子及视差计算 |
| 页面进入后台 | 暂停绘制，回到前台时重置时间基准 |
| Canvas 不可用 | 保留原背景与所有内容 |
| 本地存储不可用 | 使用内存偏好与系统设置，页面不报错 |
| JavaScript 加载失败 | 所有文章与入口仍可使用 |

装饰画布设置 `aria-hidden="true"` 和 `pointer-events: none`。关闭动态时停止实际 JavaScript 绘制循环，不能只靠 CSS 隐藏画布。

## 8. 技术实现方案

### 8.1 技术选型

| 功能 | 实现方式 |
| --- | --- |
| 入场、悬停、音柱 | CSS `transform`、`opacity` 和状态类 |
| 分区显现 | `IntersectionObserver` |
| 微光粒子 | 单个 Canvas 2D |
| 绘制与视差调度 | `requestAnimationFrame` |
| 自适应画布 | `ResizeObserver` 与受限像素密度 |
| 页面转场 | 现有 Astro `ClientRouter` |
| 偏好保存 | `localStorage`，失败时回退 |

第一版无需新增大型动画库、WebGL、后端服务和外部动画 CDN。

### 8.3 配置管理

在配置文件中集中维护：

- 粒子总开关、桌面与手机数量上限。
- 粒子大小、透明度、速度与明暗周期。
- 日间与夜间颜色。
- 鼠标影响幅度、平滑系数。
- 背景视差开关与最大位移。
- 画布像素密度上限。
- 入场位移、时长与错开时间。

CSS 中统一维护反馈时长、页面切换时长和缓动曲线，避免每个组件定义不同节奏。

### 8.4 运行生命周期

```text
页面就绪
  → 读取系统设置和用户偏好
  → 初始化本页轻量交互
  → 如果首页存在且允许动态，加载粒子模块
  → 建立画布、观察器和唯一动画循环

首屏离开视野 / 页面进入后台 / 动态关闭
  → 取消动画帧，暂停计算

重新可见且允许动态
  → 重置上一帧时间，恢复绘制

Astro 页面切换前
  → 销毁本页动画实例
  → 取消动画帧
  → 断开观察器
  → 移除本页监听器

Astro 新页面加载后
  → 重新按当前页面初始化一次
```

实现要求：

- 使用 `astro:page-load` 和 `astro:before-swap` 对接现有导航。
- 初始化函数必须幂等，重复调用不会产生多个画布或动画循环。
- 全局偏好监听只绑定一次；本页动画监听随页面销毁。
- 异步加载粒子模块期间如果已离开首页，必须取消后续初始化或检查挂载目标是否仍有效。
- 页面转场中的粒子画布不跨页持久化；音乐按现有机制保留。

### 8.5 粒子实现

1. 根据首屏尺寸和设备类型计算粒子数量。
2. 为每颗粒子分配位置、速度、半径、透明度、相位和调色。
3. 按帧间时间差更新位置，避免高刷新率设备上运动更快。
4. 对时间差设置合理上限，避免从后台返回时粒子大幅跳动。
5. 使用低频、平滑的扰动形成轻微漂浮。
6. 对文字区域与首屏底部应用透明度衰减。
7. 使用预生成的少量柔光纹理或简单径向渐变，避免每帧大量创建对象。
8. 重绘时复用对象；尺寸变化时再更新画布。

Canvas 像素密度初始上限建议为 1.5～2，手机可进一步降低。视觉单位使用 CSS 像素，避免像素密度变化影响粒子大小与速度。

### 8.6 分区显现实现

- 默认样式保持内容可见。
- 只有脚本成功初始化后，才对适合显现的区域设置准备状态。
- 已经位于视野内的区域及时显示，不等待用户额外滚动。
- 键盘焦点进入区域时立即显示。
- 动画完成后解除观察，不重复播放。
- 不隐藏文章正文，也不对整个长页面设置初始透明。

## 9. 性能预算

| 项目 | 目标 |
| --- | --- |
| 新增动效 JavaScript | 压缩后争取不超过 15KB，以构建结果为准 |
| 新增外部依赖 | 第一版不增加大型动画库 |
| 首页持续绘制 | 最多一个统一调度循环 |
| 离开首页后的粒子绘制 | 0 |
| 非首页粒子模块 | 不主动初始化或加载 |
| 动效导致的布局位移 | 目标为 0 |
| 移动端 | 优先平稳与节能，必要时降低粒子数量或绘制频率 |

性能评估使用改造前后的同环境对照，观察首屏加载、滚动流畅度与脚本执行。不能用单次 Lighthouse 分数作为全部结论，也不能仅凭粒子数量承诺所有设备稳定满帧。

## 10. 实施步骤

### 阶段一：建立基线与动效基础

1. 记录当前首页、文章页的桌面与手机画面。
2. 确认页面转场、音乐持久化、搜索、目录现有行为。
3. 建立集中配置、动效样式和偏好管理。
4. 实现生命周期清理及静止模式。

完成标准：开关可用，系统设置有效，初始化不会重复。

### 阶段二：首页氛围

1. 接入首屏粒子画布。
2. 完成日夜调色及文字区域衰减。
3. 增加标题分层入场。
4. 增加桌面轻微视差和鼠标风向响应。
5. 完成手机轻量配置。

完成标准：画面有层次，标题清楚，首屏点击与滚动正常。

## 12. 部署方案

### 12.1 沿用现有流程

```text
本地开发与检查
  → 提交并推送到现有部署分支
  → Cloudflare Pages 执行现有构建
  → 发布 dist/ 静态产物
```

保持：

```text

```

无需新增 Cloudflare Worker、数据库、服务端适配器或付费动画服务。具体部署分支和控制台设置应沿用项目现状；本方案未读取 Cloudflare 控制台配置。


```sh

```

### 12.3 发布后检查

- 验证首页动画与手机静止/轻量模式。
- 验证静态资源加载、分类链接、文章打开及旧地址重定向。
- 验证音乐和主题偏好在页面切换后的行为。
- 比较发布前后的首屏与滚动体验。

### 12.4 回退方案

实现时为粒子与视差保留独立总开关。若出现性能问题，可以先关闭持续氛围动效，保留其他轻量反馈并重新构建。

如需完整回退，回退本次动效提交或使用现有平台提供的历史部署恢复方式。内容数据与文章地址不依赖动效，因此回退不需要迁移文章。

## 13. 风险与处理

| 风险 | 处理 |
| --- | --- |
| 背景原有光点与粒子叠加过密 | 从低密度开始，使用真实背景调参 |
| 首屏文字对比度下降 | 加强文字区域遮罩，降低该区域粒子透明度 |
| 页面往返后动画叠加 | 幂等初始化，切换前完整销毁 |
| 手机上耗电或滚动不顺 | 减少数量、限制像素密度、关闭视差、不可见时暂停 |
| 内容显现脚本失败造成空白 | 内容默认可见，成功初始化后才增强 |
| 音乐持久化受到转场影响 | 保留现有持久化标识，独立验证播放器生命周期 |
| 日夜或系统偏好改变后状态不同步 | 统一偏好管理，广播变化给当前动画实例 |
